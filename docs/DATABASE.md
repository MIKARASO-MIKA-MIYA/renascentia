# База данных CMS

Миграция [создаёт схему](../supabase/migrations/20261125000100_content_editor.sql) поверх Supabase PostgreSQL, Auth и Storage.

| Таблица                      | Данные                                                  |
| ---------------------------- | ------------------------------------------------------- |
| `roles`, `profiles`          | Роли, отображаемые имена и право публикации             |
| `pages`                      | Ключ материала, публичный путь, тип и исходный документ |
| `page_sections`              | Ревизия и указатели на черновик и публикацию            |
| `content_versions`           | История документов JSONB, авторы, даты и действия       |
| `media_assets`               | Метаданные файлов в приватном бакете                    |
| `published_media_refs`       | Связи между файлами и действующими публикациями         |
| `cms_settings`, `audit_logs` | Заметка редакторам и журнал административных действий   |

Ключ страницы совпадает с её путём. Для секции к пути добавляется суффикс, например `/research/rp-001~questions`. Документ содержит версию формата, заголовок, описание, поля макета и список блоков. В каждом текстовом блоке хранится документ Tiptap.

`cms_write` в одной транзакции проверяет роль и ожидаемую ревизию, блокирует строку указателей и добавляет новую версию. При публикации та же транзакция меняет публичный указатель и привязки изображений. Восстановление копирует старую запись в новый черновик. `cms_public` читает текущие опубликованные версии. Контент проекта версии 0.0.2 служит исходным представлением для встроенных маршрутов.

Скрипт `npm run cms:seed` регистрирует 0.0.2 через `cms_seed`. Уникальный ключ защищает от дубликатов. Существующие записи остаются в базе при повторном запуске. Пока новых публикаций нет, шаблоны сайта рендерят локальные данные.
