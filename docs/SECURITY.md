# Безопасность CMS

- Вход осуществляется через Supabase Auth. Роль редактора или владельца проверяется по серверной сессии и таблице профилей. Публичной формы регистрации нет. Регистрацию в Supabase необходимо отключить при настройке проекта.
- У таблиц включён Row Level Security. Вызовы, меняющие данные, доступны серверному ключу. SQL повторно проверяет роль автора перед сохранением, публикацией, восстановлением и операциями с файлами. Публичные RPC возвращают только действующие публикации и привязанные к ним изображения.
- Сервер валидирует типы блоков, структуру документов Tiptap, ссылки и атрибуты через Zod. Публичный React-рендерер строит элементы из разрешённых узлов и атрибутов. Для YouTube используется плеер `youtube-nocookie.com`.
- Бакет `cms-images` приватный. Маршрут медиа выдаёт подписанную ссылку сроком на 90 секунд для действующей публикации или редактора. Файлы проверяются декодированием Sharp и повторно кодируются в WebP или GIF. Размер загрузки ограничен 3 МБ.
- Внешние HTTPS-адреса медиа загружаются браузером. Сервер не скачивает их. Используйте известные источники и учитывайте, что ресурс по внешнему адресу может измениться.
- Серверный ключ хранится в `.env.local` и секретах Vercel. При компрометации ключа замените его в Supabase и Vercel.
